# Pixel Knight — 像素骑士 游戏设计文档

> 模拟元气骑士核心玩法的简化版网页地牢射击游戏
> 2026-07-26

---

## 1. 概述

### 1.1 游戏定位

| 项目 | 内容 |
|------|------|
| 游戏名 | 像素骑士（暂定） |
| 类型 | Top-down 2D 地牢探索射击 |
| 技术 | 纯 HTML5 Canvas，单文件 |
| 时长 | 一局 15-20 分钟 |
| 美术 | 明亮卡通像素风，几何体+配色模拟 |
| 操作 | WASD 移动 + 鼠标瞄准 + 左键射击 |

### 1.2 游戏循环

```
开屏菜单 → 选角色(3选1) → 进入第1层
   → 探索房间(清怪/宝箱/商店) → 打Boss
   → 第2层(房间更多、敌人更强)
   → 第3层 → 最终Boss → 胜利结算
```

## 2. 角色系统

### 2.1 三个角色

| 角色 | 偏好武器 | 技能 | 生命 | 移速 | 技能冷却 |

## 8. 技术架构

### 8.1 技术栈

- **渲染**：HTML5 Canvas 2D API
- **音效**：Web Audio API（OscillatorNode 合成，无需外部文件）
- **存储**：localStorage（最高分记录）
- **部署**：单 HTML 文件，GitHub Pages 直接托管

### 8.2 核心模块

```
┌─────────────────────────────────────┐
│             Game Loop               │
│  update(dt) + render(ctx)           │
└─────────────────────────────────────┘
          │
    ┌─────┼─────────┬──────────────┐
    ▼     ▼         ▼              ▼
[地图] [玩家]  [武器/子弹] [敌人/Boss]
    │     │         │         │
    └─────┼─────────┼─────────┘
          ▼         ▼
      [碰撞检测] [粒子特效]
          │
          ▼
      [UI渲染] [状态管理]
```

### 8.3 状态机

```
MENU → CHARACTER_SELECT → PLAYING → BOSS_FIGHT → SHOP → NEXT_FLOOR
                                                      ↓
                              GAME_OVER ←────────────────
                                    ↓
                          VICTORY / MENU
```

- `PLAYING`：探索房间，清怪
- `BOSS_FIGHT`：Boss 战斗，清完后 → NEXT_FLOOR 或 VICTORY
- `SHOP`：商店房，购买后继续探索
- 死亡 → GAME_OVER → 回 MENU

## 9. 实现要点

### 9.1 Canvas 渲染策略

- 主 Canvas 居中显示，固定游戏分辨率（如 960×640），CSS 缩放适配窗口
- 背景色：深色地牢地板 (#1a1a2e)
- 墙壁：像素风格砖块纹理（代码绘制）
- 角色/敌人：几何体组合绘制（矩形+圆形+三角形）
- 子弹：小圆点，按词缀着色
- 粒子效果：击杀/爆炸时生成 10-20 个小粒子，渐隐消失

### 9.2 地图生成算法

1. 在 4×3 网格中随机选择连通路径
2. 保证入口 → Boss 之间有可行路径
3. 在分支路径放置宝箱房和商店
4. 每个房间随机放置敌人（数量随楼层递增）

### 9.3 碰撞检测

- 圆形碰撞（玩家/敌人/子弹）：圆心距 ≤ 半径和
- 矩形碰撞（墙壁/房间边界）：AABB 检测
- 弹幕碰撞：逐帧检测，子弹移速快时不跳过

## 10. 设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 渲染方式 | 纯 Canvas 2D | 零依赖、快加载、延续现有项目风格 |
| 美术 | 几何体卡通像素风 | 纯代码绘制，无需外部素材 |
| 单文件 | 是 | 便于部署，延续 rhythm_jumper.html 模式 |
| 房间结构 | 4×3 网格程序生成 | 简单可控，每局不同 |
| 音效 | Web Audio API 合成 | 无需外部文件，体积小 |
